# Безопасность MailCheque

## Защита паролей

С версии проекта с защитой паролей, все пароли в конфигурационных файлах хранятся **в зашифрованном виде**.

### Как это работает

1. **Шифрование**: Используется библиотека `cryptography` с алгоритмом Fernet (симметричное шифрование)
2. **Ключ шифрования**: Генерируется на основе уникального идентификатора машины (имя компьютера + имя пользователя)
3. **Файл ключа**: Файл `.key` хранит соль для генерации ключа шифрования

### Важно знать

⚠️ **НЕ УДАЛЯЙТЕ файл `.key`** - без него пароли не смогут быть расшифрованы!

⚠️ **Файл `.key` привязан к машине** - если скопировать config.json на другой компьютер без .key файла, пароль не расшифруется

### Структура файлов

```
MailCheque/
├── config.json          # Зашифрованный пароль
├── .key                 # Ключ для расшифровки (НЕ УДАЛЯТЬ!)
└── MailCheque_Portable/
    ├── config/
    │   └── .key         # Отдельный ключ для портативной версии
    └── config.json      # Зашифрованный пароль
```

### Миграция существующих паролей

Если у вас есть незашифрованные пароли в config.json, запустите:

```bash
python migrate_passwords.py
```

Скрипт автоматически:
1. Найдет все config.json файлы
2. Зашифрует незашифрованные пароли
3. Создаст необходимые .key файлы

### Где хранится пароль

**В файле config.json**:
```json
{
  "password": "Z0FBQUFBQm9fenZJQUdwU2VDR1BsdEVjcnBUOHV3QmN2T19nREI1SkkwY29YLUJmcUdFYXMwT1pSYzNVR0h3TmhYQjNrVUxJZjV4YTBNdkVlMnFzUWYxMFBlZzQyQXlZeVI5N0NyRlRtdW82U2lQdEJGVXZJMGM9"
}
```

**В памяти приложения**: Автоматически расшифровывается при загрузке

### Что защищено

✅ Пароли в `config.json` зашифрованы  
✅ Пароли в `MailCheque_Portable/config.json` зашифрованы  
✅ Файлы `.key` добавлены в `.gitignore`  
✅ Автоматическая миграция при запуске приложения

### Что НЕ защищено

❌ Пароли в логах `logs.json` (не используется для хранения паролей)  
❌ Пароли в оперативной памяти во время работы приложения (стандартное поведение)

## Рекомендации

1. **Используйте пароль приложения**, а не основной пароль от почты
2. **Не храните файл .key в публичных репозиториях** (уже в .gitignore)
3. **Делайте резервные копии .key файла** для восстановления доступа
4. **При переносе на другую машину** скопируйте и config.json, и .key файл вместе

## Как работает автоматическая миграция

При каждом запуске приложения класс `Config` автоматически проверяет:
- Если пароль в config.json не зашифрован → зашифровать и сохранить
- Если пароль уже зашифрован → использовать как есть

Поэтому достаточно один раз запустить приложение после обновления кода.
